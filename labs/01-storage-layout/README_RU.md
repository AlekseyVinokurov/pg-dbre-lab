# Лаборатория 01 — Физика хранения и DDL

[English](README.md) | [Русский](README_RU.md)

**Статус:** В работе

## Цель

Понять, как PostgreSQL физически хранит строки и почему типы данных, выравнивание, NULL-значения и TOAST могут заметно влиять на размер таблицы и характер чтения данных.

Эта лаборатория специально начинается с физики хранения, а не с тюнинга SQL-запросов.

## Вопросы, на которые нужно ответить

- Что физически хранится внутри heap-страницы PostgreSQL размером 8 KiB?
- Какие накладные расходы несёт каждая строка?
- Когда PostgreSQL добавляет padding из-за выравнивания типов?
- Как порядок колонок влияет на ширину строки?
- Как NULL bitmap влияет на layout строки?
- В каких случаях PostgreSQL использует TOAST и что именно он делает с крупными значениями?
- Как ширина строки и плотность строк на странице влияют на общий размер таблицы и количество чтений буферов?

## Порядок эксперимента

1. Зафиксировать версию PostgreSQL и параметры окружения.
2. Создать отдельную схему для лаборатории.
3. Использовать только синтетические данные.
4. Измерить базовый размер таблицы и связанных объектов.
5. Сравнить альтернативные варианты физического layout при одинаковом логическом наборе данных.
6. Изучить поведение страниц и строк через штатную статистику и диагностические средства PostgreSQL.
7. Сначала зафиксировать наблюдения, и только потом делать выводы.
8. Объяснить физику результата своими словами.
9. После завершения эксперимента удалить лабораторную схему.

## Что нужно сохранить как доказательство

- DDL каждого сравниваемого варианта
- количество строк и распределение данных
- результаты `pg_total_relation_size` и `pg_relation_size`
- среднюю ширину строки, если она важна для эксперимента
- данные о page density / tuple layout, если они доступны
- планы запросов, использованные для сравнения чтения
- точные измерения до и после изменения

## Критерий завершения

Лаборатория считается завершённой только тогда, когда в репозитории есть воспроизводимый эксперимент, показывающий как минимум один измеримый эффект физического layout, и есть письменное объяснение механизма PostgreSQL, который этот эффект вызвал.
